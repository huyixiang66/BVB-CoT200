# Room-size交接

## 入口与依赖

此目录为独立可运行包，在此目录下设置 `PYTHONPATH=$PWD/src`。默认入口按 README 执行。需要另行checkout上游 `methods/bvb-v10_2-full-pipeline-20261110`（验证提交7568fce70c45），把config.v10_root指向该checkout的methods/adaptive_frame_selection；本分支未复制或替换学长上游源码。

流程：已有LingBot原帧/位姿缓存选帧 → 原帧估计区域长宽和参照范围 → V10_2联合生成Blender Python → 程序固定建筑尺寸并验收 → 单俯视参照尺寸上沿QA。正常3次Astra High调用。无GT输入，无按题号分支；不重跑LingBot/DINO，需先备好正确匹配的缓存。

订阅客户端是外部依赖（提供auth.py/call.py及make_content/infer接口），不随本包携带凭据。只有CPU构图与Blender在实验服务器运行；若服务器网络不通，可通过pipeline.run的backend/renderer回调接本地轻量传输，但本包不包含服务器专用代理和隧道脚本。Python最低3.10；不需在共享环境升级，使用独立环境。

## 已测结果与边界

七场景开发实验81.82%不等于此自动通用代码的准确率。50题运行：baseline50题完成；方法47题完成，原始配对MRA57.06%→58.41%，另3题失败/阻塞。后续修正属于独立实验，不能混称一次冻结算法评测。

已验证的修复现在默认生效，无需用户换脚本：
- `contracts.py`区分不同physical space之间的敞口与同空间分块；前者允许有效通口，后者仍要求整个公共边界开放。
- `blender_scene.py`支持同一空间跨分块的实例、显式测量排除轴、reference_euler与measurement_matrix，保留家具网格和真实测量，不把估计值冒充测量值。
- qa_axes包含高度时只选可用的水平长宽；竖立物体的非水平轴不用于俯视参照。0.8可见比例、0.005投影占比及完整画幅门槛不变。
- V10输出的字面量render.engine='BLENDER_EEVEE_NEXT'自动兼容为Blender5的BLENDER_EEVEE；只改引擎赋值，不改家具或原始模型响应。
- `repair_*.py`现在只是旧调用的兼容入口，委托给默认模块，不再维护两套逻辑。

运行前按README准备V10_2 checkout、缓存、Blender/bubblewrap和订阅客户端即可用原CLI；不需要手工拼接修复版。旧运行的source hash将变化，应使用新输出目录，避免静默混用历史产物。

测量元数据只有显式提供时才生效：`measurement_exclude_axes`是该部件不参与测量的轴列表（部件仍可见）；`reference_euler`是实例局部XYZ朝向；`measurement_matrix`把世界坐标转换到该部件的测量坐标。缺省仍测量整个实例，不自动猜哪些附件应排除。历史逐题手工添加的元数据不作为通用硬编码上传；未知物体不能据此保证自动通过。

参照描述目前可能丢失“单段桌面/整排桌子”“整床/床垫”的语义。后续需明确对应的可见边界；不能为了提高成绩改参照尺寸。已有2699同图修正表明这能避免错认，但未完成自动语义修正模块。668采用人工检查后补6帧及额外证据提示，尚未通用化，本包不含按题号补帧。

原帧估计的长宽会被固定到建筑中。因此几何验收通过只说明忠实遵守估计，不能证明真实面积准确。未完整看到边界时，仍可能把低置信度长宽固化；不应宣称LingBot提供了真实米制尺寸。
