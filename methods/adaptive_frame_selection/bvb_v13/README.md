# BVB V13

从 `bvb_v12_light_2` 独立派生，精简重构输入、场景参数输出和逐图答题输出。

重构使用 `compact-scene-v2` 与 `task-essential-geometry-v1`。默认每个物理实例一个基本体，仅在影响身份、轮廓、朝向、测量表面、遮挡或通路时添加零件。这是按题型约束模型生成的策略，不对既有场景强制删零件：距离题保留最近表面和凹空区域，尺寸题保留全部外轮廓，计数题保持不同实例，路线题保留通路与障碍，房间题保留完整地面边界和必要尺度物体。

新输出示例：`{"v":2,"o":[[0,[1,2,1],[2,1,2]]],"a":[]}`。物体行依次为类别编号、位置、几何和可选旋转；编号来自问题物体列表，不是新的语义判断。尺寸数组默认表示中心方块，旋转默认零；圆柱等使用 `["c",dx,dy,dz]`，必要复合结构使用 `{"p":[零件]}`。类别名称、颜色、实例 ID、材质和运行元数据由本地补齐；room 模式仍允许模型给出必要家具的简短类别名。新推理必须返回 v=2；旧 v1 场景仍可本地读取、验证和编译。每次请求保存原始 scene-spec.json 与本地展开的 scene-normalized.json，后者不计入模型输出。修复仍沿用完整替换流程。

- 第一轮只看一张半分辨率渲染图。
- 看不清、遮挡、身份/空间关系不确定或需要更多视角时，模型只应返回 `NEED_MORE_VIEWS`，不生成暂定答案、理由或解释。
- 程序追加一张图，使用累计视角再次请求；不会另加独立的预审 API 调用。
- 证据充分时只输出选项字母或数字，不输出 JSON、理由、置信度或分项解释。本地代码校验答案类型与选项范围，并保存 answer.txt 和带运行元数据的 answer.json。
- 所有候选视角均不足时，保存 `status: insufficient_evidence`、`answer: null`，运行状态为 `insufficient-evidence`，不强行给答案。断点续跑不会重复这些请求；要补充新的证据，请使用新输出目录。
- 非法选项、非有限数、负数、非整数计数、JSON 或附带解释的输出会被拒绝；不偷偷提取答案，也不额外启动修复调用。原始响应和 token 用量完整保留。旧的长理由、分项计数、路线解释等输出校验不再用于新协议；语义约束保留在答题提示词中。

沿用 light 的单帧语义审核、精确缓存、短重构提示词、紧凑场景 JSON、本地 Blender 编译、fixed 几何选视角、半分辨率自制图和缺目标 0.5fps 恢复。原始视频帧不降分辨率。

推理强度仍为 `high`。短输出约束减少不确定轮次的可见回答；reasoning token 的实际变化需要独立实测。

重构文字使用 `scene-evidence-tables-v1`：字段名只声明一次，聚类用 gN 短编号，逐帧观测与软锚点用数组表格。保留组的几何权限、观测状态、置信度、相机和锚点证据；聚类编号不等于物体实例。仅在帧成员关系能精确还原时省略组内重复时间列表。删除无几何意义的题目/场景 ID 和检测 peak ID；检测框保留 0.1 像素，相机精度不变，锚点沿用四位小数。原始 input.json 不变，模型输入及编号映射另存每次请求的 evidence-transport.json。图片、选帧、重构输出协议及 reasoning 档位不变。

```sh
.venv/bin/python -m bvb_v13 verify
.venv/bin/python -m bvb_v13 --help
.venv/bin/python -m bvb_v13 run --out NEW_PREPARED_OUTPUT --view-selection fixed
.venv/bin/python -m unittest discover -s bvb_v13/_runtime/tests_v12
```

`prepare`、`workflow`、`room-build` 的参数沿用 light。结果目录和冻结请求与旧版隔离，禁止把旧的逐图请求目录直接作为新版结果继续运行。

本版独立 65 题实验记录于 results/bvb-v13-09c1414f1b-65qa-20261115；已完成的 `results/bvb-v12-light-09c1414f1b-65qa-20261114` 使用原 light，不能将其结果作为新版实测结果。

光流去重原型保持暂停。重构原始帧已启用 0.5 秒时间去重：按时间排序，保留最早帧，距最后保留帧 ≤0.5 秒的后续帧丢弃；不是连续时间链合并，也没有按组保底例外。同一时刻保持原顺序。审核与参考示意图不受影响，原始 input.json 不变。模型的逐帧元数据、图片和建筑证据索引均使用筛选后的顺序；不会把丢弃帧的检测框或组成员关系转移到相邻帧。reconstruction-frame-selection.json 记录前后数量、原索引和失去全部图片的组，后者明确标记为仅有软证据。每次请求的 reconstruction-image-inputs.json 记录实际发送的原图。

Counting 答题使用 qa-color-legend.json 的完整 category_palette，保留同类多色、颜色可复用和零件不等于实例的说明；不传入实例清单或计数。该修复的 12 题 QA-only 重跑独立存放于 results/bvb-v13-counting-palette-fix-12-20261115，原 65 题记录不覆盖。

物体尺寸题答题允许原图：从重构经0.5秒去重后的既有证据中，先选目标检测面积与置信度较高的一帧，再按时间差补充，最多3张，内容相同的原图去重。首轮1张渲染图+1张原图，仍不充分时交替增加一张原图或渲染图。原图不缩放，自制图仍半分辨率；不重新扫描视频。图片输入清单记录各自来源、hash、尺寸与时间戳，成本记录包含原图输入。颜色图例仅约束渲染图，原图提供真实外观和相对尺寸线索，不代表米制标定。其余题型流程不变。已完成或证据不足的旧回执保持冻结，使用新输出目录才能采用此策略重跑。此改动尚未做真实API重跑。
