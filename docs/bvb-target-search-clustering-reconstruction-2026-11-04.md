# 目标搜寻、几何外观聚类与重建对照（2026-11-04）

代码在 [`methods/bvb-region-reconstruction-20261104/`](../methods/bvb-region-reconstruction-20261104/)，只含脚本和预设，不含数据产物。本文记录这一轮做了什么、结论是什么、边界在哪。

## 一、目标搜寻：换检测器、换提示词、放宽阈值

主案例是 `3db0a1c8f3` 的嵌入式冰箱，第二案例是 `blanket` 漏检。用同一批冻结诊断帧（冰箱 13 正例／12 负例，毯子 10 正例／12 负例），每张正例要求该类最高分框与人工参考框 IoU ≥ 0.50。

| 模型与提示 | 阈值 | 最高分框命中 | 负帧误报 |
| --- | --- | ---: | ---: |
| Tiny 原 20 类 | 0.20／0.25 | 5/13 | 3/12 |
| Tiny 原 20 类 | 放宽 0.12／0.17 | 6/13 | 3/12 |
| Tiny + `built-in refrigerator` | 常规 | 8/13 | 9/12 |
| Base 原 20 类 | 常规 | 0/13 | 1/12 |
| Base + `built-in refrigerator` | 常规 | 10/13 | 7/12 |
| MM Base 原 20 类 | 常规 | 11/13 | 5/12 |
| MM Base + `built-in refrigerator` | 常规 | 11/13 | 5/12 |

真冰箱能稳定框中：MM Base 保留原词表，在 114.50／114.73／115.00／115.27 秒四帧全部框中微波炉下方那台冰箱。Base 原词表四帧全无，加上 `built-in refrigerator` 后四帧全中，分数 0.36–0.39，若沿用 0.50 的波峰门槛不能保证保留。

结论：**收益主要来自换模型和加提示词，放宽阈值只找回个别漏框**。提示词变多也不等于波峰选择变好——MM 加 `built-in` 后 115 秒分数反而降到 0.461。当前冰箱输入优先用 MM Base 原词表、常规阈值的候选，且保留多候选，132 秒等误检仍在。

只审 `refrigerator` 与只审 `built-in refrigerator` 也各跑过一轮：Base 命中 8/13 与 10/13，负例误报 8/12 与 12/12；MM 分别 11/13 与 10/13，误报 11/12 与 12/12。去掉其他类别并不比保留原词表稳。

1758 的床毯：Tiny 7/10、Base 9/10、MM 6/10，Base 常规阈值误报 0/12，这一场景以 Base 更稳。同场景的鼠标没有独立人工参考框，不报准确率。

## 二、几何＋外观加权聚类

帧对分数 `g + 0.75 · s · (1 − g)`，complete-link 合并。预设是外观系数 0.75、外观生效的最低几何分 0、至少 1 对帧支持、合并门槛 0.468（`preset/geometry-appearance-075.json`）。

- 2607（只含门类，36 张冻结帧）：33／47／138 秒同一扇玻璃门的 `door-p02/p03/p06` 合进一组；132 秒误框另成一组；188 秒附近衣柜板误框进了 181／217 秒木门组，约 85 秒的木门仍独立。
- 2077（只保留椅子，83 张）：圆桌旁深色椅子 `chair-p06/p07/p12` 同组，人工看原帧后确认。
- 2077（全题 166 张）：`chair-p07/p12` 配对分 0.869，最终仍分开——各自先与其他类别成组，complete-link 链上有低于 0.468 的边。

验收看三件事：同一区域有没有被拆散、不同区域有没有被误合并、每组够不够支撑局部重建。一个组可以覆盖多个相关物体，「相机看向哪个三维区域」用位姿结合深度估计，所以门内门外两个相反朝向可以进同一组。

## 三、按 V5 流程做三场景小规模重建对照

六题、25 个区域组（VSI 1585／2607、STI 6／8、MMSI 0645／0734）。检测保持 Tiny，分组用上面的 0.75 预设，按类别组织；VSI 复用冻结 V3 帧，1585 另补之前 Tiny 加 `built-in refrigerator` 在 113.5–115.75 秒的厨房候选。25 个 `scene-transport.json` 全部落盘，由父会话按 V5 schema 验证后交给服务器 Blender 编译，结果原样共享坐标拼合。

已知缺陷：跨组同一物体可能重复生成，1585 的三组沙发、2607 多个木门假设在合并后没有额外去重；本次未做 QA。

## 额度问题

一次同时启动三个 Astra 子代理，六题拆成 25 组，多图多步几何推理叠加，令消耗集中发生（运行前账户接口 60%，中途 94%，另一次返回 44% 且 reset 时间不同，读数不一致，无法准确分摊）。MMSI 代理在 25 个文件全部落盘后于收尾报告 usage limit。后续按单题推进、每批核查用量，复用本次 25 组原始输出。

## 结论与下一步

检测侧已能稳定框到真冰箱，剩下的误差主要来自峰筛选和提示词与波峰门槛不匹配；聚类的新权重在 2607 调通、在 2077 椅子题上迁移成立，但仍受 complete-link 链上的弱边限制；重建流程跑通但只到「能出图」的程度，缺少 QA 和跨组去重。
